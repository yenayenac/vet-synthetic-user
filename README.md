# 동물병원 보호자 합성사용자 · 합성 모더레이터

「AI기반 서비스기획과 검증」 조별 프로젝트 · 이상훈 · 허준영 · 최예나

---

## 이게 뭐 하는 건가

AI 두 명이 서로 인터뷰를 합니다.

| | 역할 | 사는 곳 |
|---|---|---|
| **보호자 AI** | 답한다. 근거 자료 안에서만 | `knowledge_base.py` |
| **모더레이터 AI** | 묻는다. 더 캘지 넘어갈지 판단한다 | `moderator.py` |

사람은 버튼만 누릅니다. 10문항이 자동으로 돌고, 끝나면 포스트잇용 니즈가 세 종류(명시적·암묵적·잠재적)로 나뉘어 나옵니다.

---

## 모더레이터는 어떻게 판단하나

매 턴마다 이것만 봅니다.

**더 캔다 (probe)**
- 추상적이다 — "불편했어요", "좀 그랬어요"
- 일반론이다 — "보통 그렇죠"
- 한 문장 단답이다
- 감정만 있고 그 순간 무슨 말을 했는지가 없다

**넘어간다 (next)**
- 구체적 장면이나 실제 발화가 있다
- 금액·항목·횟수 같은 사실이 있다
- "그건 제 경험에 없어요"라고 했다 → 자료 밖이라 더 캐면 지어낸다
- **이미 세 번 되물었다** (교수님 지침: 최대 3회)

꼬리 질문은 네 가지 형태에서만 만듭니다.
`그때 뭘 물어보고 싶으셨어요?` / `왜 그렇게 하셨어요?` / `그 말을 하면 어떤 일이 생길 것 같았어요?` / `그게 평소와 달랐나요?`

금지: `불편하셨죠?`(유도) · `어떤 기능이 있으면 좋을까요?`(기능) · `보통 보호자들은…`(일반론) · 평가·조언·위로

## 올리는 순서

### 1. GitHub 저장소 만들기
github.com → **New repository** → 이름 `vet-synthetic-user` → **Public** → Create

### 2. 파일 네 개 올리기
**Add file → Upload files** 에 이 네 개를 끌어다 놓고 **Commit changes**

```
app.py
knowledge_base.py
moderator.py
requirements.txt
```

### 3. Streamlit Cloud 연결
share.streamlit.io → **Sign in with GitHub** → **Create app** → **Deploy a public app from GitHub**
- Repository: 방금 만든 저장소
- Main file path: `app.py`
- **Deploy** 누르고 2~3분 기다립니다

### 4. API 키 넣기 — 가장 중요한 단계
배포 화면 오른쪽 아래 **Manage app → Settings → Secrets** 에 아래 한 줄을 넣고 **Save**

```
ANTHROPIC_API_KEY = "sk-ant-여기에키"
```

> **키를 GitHub 파일 안에 절대 쓰지 마세요.**
> 저장소가 Public이라 커밋하는 순간 전 세계에 공개되고, 자동 스캐너가 몇 분 안에 찾아내 요금이 청구됩니다.
> Secrets 는 GitHub이 아니라 Streamlit 서버에만 저장됩니다.

키는 console.anthropic.com → API Keys 에서 만듭니다.

## 쓰는 법

1. 왼쪽에서 **인물**과 **모드**를 고른다
2. **인터뷰 자동 진행** 을 누른다 → 10문항이 자동으로 돈다
3. **니즈 · 포스트잇** 탭 → **니즈 뽑기**
4. 전사록(.md)과 포스트잇(.csv)을 내려받는다
5. 인물을 바꿔 1~4를 반복한다 → 3명 돌리면 포스트잇 20장이 넘는다

### 모드 차이

| 모드 | 하는 일 | 언제 |
|---|---|---|
| **검증** | 자료에 문장으로 있는 것만 말한다. 없으면 "그건 제 경험에 없어요" | 과제에 제출할 자료를 뽑을 때 |
| **탐색** | 자료 기반 추론을 허용하고 `(추론)`이라고 표시한다 | 가설을 넓힐 때 |

### 비용
인터뷰 1건에 모델 호출이 30~50회 발생합니다. 처음에는 **Haiku** 로 돌려 흐름을 확인하고, 자료로 쓸 것만 **Sonnet** 으로 올리세요.

## 인물 넷

| 인물 | 유형 | 비중 | 한 줄 |
|---|---|---|---|
| 윤다은 | 당황한 초보 | 32% | 설명을 들었지만 판단할 수 없어 결제 뒤에 커뮤니티에 묻는다 |
| 정민호 | 예습한 초보 | 14% | 가격을 다 알아봤는데 "재활은 생각 못 했다"는 빈칸이 나온다 |
| 박미경 | 버티는 베테랑 | 38% | 금액을 전부 아는데도 묻지 않는다 |
| 이수진 | 계획하는 베테랑 | 16% | 묻고 거절한다 — 가설을 깨러 넣은 반증 인물 |

축은 **반려 경험(능숙도) × 상황 준비정도**. 나이·소득이 아니라 행동으로 나눴습니다.
비중 32/14/38/16은 아직 **배분(안)** 입니다.

## 데이터에 없는 것 — 숨기지 않는다

- **보호자 연령**: 132건 중 나이를 밝힌 글이 **2건**. 네 인물의 나이는 전부 통계(No.5·No.6)에서 유도한 **추정값**
- **성별 · 소득 · 월 양육비**: 수집된 값 0건
- **거주 지역**: 수도권 표기는 추정
- **결정권자 구조**: 확인된 행이 거의 없음

→ 검증 모드에서는 이 항목을 묻지 않습니다. 물으면 인물이 지어냅니다.

## FGI 좌담회 모드

같은 질문을 여러 인물에게 **동시에** 던집니다. 두 번째 사람부터는 앞사람 답을 듣고 답하므로, 동의하거나 반박합니다.

**1:1에서는 안 나오는 데이터가 여기서 나옵니다.**
윤다은이 "묻고 싶었는데 못 물었어요"라고 하는 바로 옆에서 이수진이 "저는 포함 범위부터 확인해요"라고 받습니다. 두 사람의 어긋남 자체가 분석 재료입니다.

### 쓰는 법
1. **FGI 좌담회** 탭 → 참여자 고르기 (3명 권장)
2. 질문을 10문항에서 고르거나 직접 입력 → **좌담회에 질문 던지기**
3. 한 바퀴 끝나면 **참여자 반응 유도** → 서로의 말에 반응하게 한다
4. 전사록 내려받기 → **니즈 · 포스트잇** 탭에서 `FGI 좌담회`를 골라 니즈 뽑기

### 지금 빠진 것 — 공급자
보호자끼리만 모으면 "병원이 설명을 안 해줬다"로 합창이 끝납니다.
**수의사가 "안 물어보셔서 설명을 안 했다"고 말하는 순간**, 침묵이 한쪽 탓이 아니라 양쪽이 만든 구조라는 게 드러납니다. 그게 이 프로젝트가 찾는 장면입니다.

준영 님 패널에 재료가 이미 있습니다 — **수의사 7건 · 간호사·데스크 2건 · 가족 7건**.
그 원문을 `knowledge_base.py`의 `EVIDENCE`에 번호째로 붙여넣고 `STAKEHOLDERS` 틀을 채우면 바로 돕니다.

> 자료 없이 빈칸을 상상으로 메우지 마세요. 그 순간 FGI가 창작이 됩니다.
